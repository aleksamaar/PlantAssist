## 🎯 Следующая большая задача: второй пользователь

Есть конкретный запрос: знакомый хочет пользоваться приложением с компьютера и
телефона, получать обновления и давать обратную связь. **У каждого пользователя
должна быть своя коллекция** — это решено.

### Главная проблема

Приложение написано под одного человека: пароль один, `data.json`, `photos/`,
`achievements.json` — общие. Дать пароль означает пустить человека в свою
коллекцию. Разводить данные придётся до того, как отдавать доступ.

Хорошая новость: поверхность правки маленькая. Пути к данным упоминаются в
`app.py` около сорока раз, и почти все — внутри восьми функций загрузки-сохранения
и обработчиков фото.

### Что делаем (этап 1)

Аккаунты в самом простом виде, без регистрации и почты:

- `users.json`: логин → хеш пароля (`hashlib.scrypt`, без внешних зависимостей) → id;
- данные по папкам `data/<user_id>/`, фото тоже;
- в сессии `user_id`, вход по логину и паролю;
- аккаунты заводятся вручную скриптом;
- бэкап и восстановление становятся пер-пользовательскими — иначе один скачает
  архив со всеми;
- перенос текущих данных в свою папку, с проверкой числа растений, фото и
  достижений до и после. **Бэкап до начала обязателен.**

Плюс два маленьких куска, пока это дёшево:

- **прослойка для фото** (сохрани/отдай/удали) — сейчас код пишет в папку
  напрямую; десяток строк сейчас экономят день при переезде в объектное хранилище;
- **сжатие фото при загрузке** до 1600px — сейчас сохраняются как есть, телефон
  снимает по несколько мегабайт.

### Когда переходить к следующим этапам

Не заранее, а по сигналу:

| Сигнал | Что делать |
|--------|-----------|
| Потери данных или больше пяти пользователей | JSON → SQLite (один файл, транзакции, без новой инфраструктуры) |
| Фото занимают больше половины диска | Фото в Cloudflare R2 или Backblaze B2, в базе только ключи |
| Приходят незнакомые люди | Регистрация, восстановление пароля, удаление аккаунта |
| Не хватает процессора или надоела кнопка продления | Платный тариф или VPS |

Фото упрутся первыми: 44 снимка = 12.7 МБ, около 290 КБ на штуку.

**SQLite — не времянка**, он спокойно тянет сотни пользователей такого
приложения. Docker, Postgres и CI при двух пользователях не нужны.

### Обратная связь

Без этого пользователь напишет «что-то сломалось». Минимум: короткий хеш коммита
в интерфейсе (чтобы по скриншоту понять версию) и кнопка «Сообщить о проблеме».
И раз в неделю спрашивать самой — сам он почти наверняка не напишет.

## 🐛 Известная проблема: Яндекс Диск ломает git

**Симптом:** после переноса папки Диска синхронизация удалила часть git-объектов
и файл `.git/index`. Проверено экспериментом: созданный `index` исчезал через 5 секунд.

**Лечение** (данные не теряются — код на GitHub, растения в облаке):

```bash
git fetch origin   # если пропали объекты ("bad object", "invalid sha1 pointer")
git reset          # если статус показывает все файлы как удалённые (D)
git fsck           # проверить, что всё чисто
```

**Риск:** может повториться при массовой переиндексации Диска. **Повторилось
27 июля** (индекс снова показывал все файлы как удалённые) — вылечено `git reset`.
Раньше (годами, на старом месте внутри Диска) проблем не было.

Если продолжит повторяться — вынести проект из папки Диска, а бэкапы направить
внутрь Диска через `PLANTASSIST_BACKUP_DIR` (уже поддерживается в `backup.py`).

## 🐛 Известная проблема: Яндекс Диск ломает `.bat`

**Симптом:** после переноса `.bat` перестали запускаться — cmd сыпал
`'cho.' is not recognized` и т.п., ничего не открывалось.

**Причина:** Диск перекодировал текстовые файлы (UTF-8, концы строк LF), а с
`chcp 65001` и русским текстом на **англ. консоли (OEM codepage 437)** парсер cmd
съедал первые символы команд.

**Лечение (сделано 27 июля):** все `.bat` (`start.bat`, `start_local.bat`,
`backup.bat`, `backup_config.bat`) переписаны в **чистый ASCII + CRLF**, без `chcp`.
Так они не зависят от кодовой страницы. **Если снова сломаются после синхронизации
Диска — держать их в ASCII+CRLF** (проверить: `file *.bat` → должно быть без
«UTF-8», концы строк CRLF).

## Как запустить и проверить

```bash
# Работа с приложением (облако)
start.bat

# Локальный сервер для разработки (данные старые!)
start_local.bat        # спросит подтверждение
py app.py              # то же самое напрямую

# Бэкап из облака в Яндекс Диск
backup.bat
```

Локально пароль не спрашивается — он включается только если задана переменная
`PLANTASSIST_PASSWORD` (она есть только на хостинге).

**Тестов и линтера нет** — всё проверяется руками в браузере.
После правки `app.py` сервер нужно перезапустить вручную.
